# 不确定性建模 —— 架构设计

> 状态：§1–§3 已确认，§4–§5 为本文首次落稿；**修正案 1–4 已采纳**（2026-10-16 两轮评审，见 §3.5、§3.6、§六、§九）
> 取代：`2026-10-15-知识增强层-design.md`（其「搜索层」被吸收为本文的「判定层」）
> 日期：2026-10-16

## 一、问题：系统不知道自己哪里不确定

当前解析管线**只认原文**，没有外部参照系。后果有四个，且都不是「功能缺失」，而是**架构缺一根支柱**：

1. 一个「只有称谓」的实体（`太祖`）和一个「名字确定、类型可疑」的实体，在图谱里**长得一模一样** —— 系统无法对自己的输出表态。
2. `太祖` 被当成一个正常名字存下来，系统**不知道**这是个不完整指代。
3. 关系抽错时只能靠原文自证，而它自己只有一份材料 —— 实测 **78.5% 的关系只有一条证据**。
4. 系统**被迫给答案**：把「太祖」当成完整实体，而不是标记「本名未确定」。

```
① 抽取（神经）    LLM 从原文读知识            ← 已有
② 校验（符号）    确定性工序过滤/投票/归并      ← 已有
③ 校验（外部）    搜索获取外部知识，交叉验证    ← 缺这一根
```

**核心目标**：系统要能**意识到自己的不确定** —— 不是「补全缺失」，而是「**知道自己的边界在哪**」。

## 二、不确定性的四类来源

| 来源 | 本质 | 触发条件 | 行动 | 终态 |
|---|---|---|---|---|
| ① 原文信息不足 | **不知道** | 称谓型 canonical 且零别名 | 搜索补本名 | `resolved` / `unresolvable` |
| ② 抽取可能出错 | **可能错** | 类型与词形矛盾 | 外部校验 | `corrected` / `confirmed` |
| ③ 归并可能出错 | **可能错** | **互斥共现**（同姓、从不共现、章节分布重叠）的疑似同一人；同段落共现仅作低置信辅助（实测 3/4 为亲属，见 §3.6） | 搜索验证 | `merged` / `distinct` |
| ④ 外部不可得 | **不可知** | 搜索无结果 | **不猜，标记** | `unresolvable`（终态） |

**两条设计原则**：

- **「不知道」和「错了」是两件事。** 前者该**标记**不该猜；后者该**验证**可修正。当前系统把两者混为一谈。
- **必须能表达终态 `unresolvable`。** 这是健全性的关键 —— 系统必须能说「我尽力了，但确实不知道」，而不是被迫给一个答案。

## 三、检测 $0 / 判定付费

### 3.1 实测（儒林外史，876 实体 / 377 关系）

| 类型 | 检测方式 | 实测 |
|---|---|---|
| ① `name_incomplete` | 称谓型 + 零别名 | **74** |
| ② `name_ambiguous` | 同姓存在「像本名」的实体 | **61** |
| ③ `type_suspect` | 类型与词形矛盾 | **15**（误报多，见 3.3） |
| ④ `alias_suspect` | 同段落共现（⚠️ 方向存疑，拟改互斥共现，见 §3.6） | **12** |
| ⑤ `relation_single_source` | `evidence_spans` 计数 | **274 / 349 = 78.5%** |

### 3.2 五类检测全部可 $0

因为它们**只依赖图谱自身** —— 实体名、别名、提及段落、证据片段。没有一项需要外部信息。

**这直接契合项目铁律①**：检测可以库内**精确重放**（预测表 + 跑完对账）。所以检测能力**可以完全进 `src/`**，是可测、可预演的确定性工序，**不需要等搜索层就绪**。

### 3.3 检测器本身也会有洞（重要）

③ 的初版检测器用 `PLACE_SUFFIX`（府/县/州/江/山/亭…）判「类型与词形矛盾」，结果把这些人误判为地名：

```
庄濯江 / 庄耀江   [PERSON]   ← 「江」是名字用字，不是地名
迟衡山 / 衡山     [PERSON]   ← 「衡山」是他的字
景兰江 / 兰江     [PERSON]   ← 「江」同上
娄瑟亭 / 娄玉亭   [PERSON]   ← 「亭」是字
```

真正的疑似只有 `老父台`（父台 = 对地方官的尊称）、`范学台`（学台 = 学政）这类**官职词被当人名**。

**结论**：通用后缀表在**中文人名上不适用** —— 「江/山/亭/楼」既是地名词尾，也是人名常用字。这与既有结论「编辑距离检『同一人』在中文人名上失效」**是同一类错误**：拿通用规则去量中文人名。

**由此得到一条新原则**：**检测器本身也需要被验证。** 检测结果应带**自身置信度**，或至少标注「此检测器已知误报率」。

### 3.4 分界线

```
检测 Detection            判定 Resolution
只依赖图谱自身             需要图谱之外的信息
确定性 · $0 · 可预演       不确定 · 需搜索 · 不可预演
→ 进 src/（可测）          → 进 Agent（离线、可缓存）
```

**架构含义**：不确定性建模**不需要等搜索层**。检测这一半现在就能做、能测、能预演；搜索层只负责「判定」，且**它的输出不影响解析管线**。

### 3.5 修正案 1：检测器置信度一等化

§3.3 已证明检测器本身会有洞，但「检测结果应带自身置信度」不能只停留在原则。落实为三条机制：

1. **检测器版本化**：每个检测器有 `detector_id + version`（同 prompt 版本管理）。每条标记携带 `{detector, version, confidence}` —— 没有置信度的标记不得产出。
2. **与管线代码同级纪律**：检测器的新增/修改必须走 $0 预演 + 预测表 + 逐条对账 + 变异自测（铁律①与变异纪律延伸到不确定性层）。
3. **宁可少标，不可错标**：直接继承 P5 归并的既定原则。拿不准的检测器先降 `confidence`，而不是先上线。

理由：不带校准置信度的检测器是一把新的坏尺子，且会批量生产错误标注 —— 本项目「坏的是尺子」的教训不能在新层重演。

### 3.6 修正案 4：检测器方向修正与第六类候选（评审增补）

**④ 的信号方向选反了。** 实测同段落共现的 12 组候选中 3/4 是亲属（父子/夫妻）——以两个名字在同一段出现，恰恰说明是**两个不同的人**。检测「同一人被拆」的正确内部信号是其反面：

- **互斥共现**：两个同姓实体**从不**在同段落共现 + 提及的章节分布高度重叠 → 疑似同一人被拆。古典小说对同一人会在不同段落轮换使用名/字/号，但极少在同一段内并用两个称呼指同一人。
- 原「同段落共现」信号降级为**低置信辅助**（按修正案 1 的置信度分级处理），不再作为主触发。

**新增第六类检测器候选：`recall_suspect`（漏抽嫌疑）。** 现有五类检测全部针对「已抽出来的东西」，而儒林 1-1 召回 83.72 意味着约 16% 的实体根本没进图——系统对「图中没有的东西」无法表态。可用的内部信号：**P0 预扫描候选集 − 最终入库实体集 = 漏抽嫌疑集**。P0 候选本身噪音大，此检测器须先验证误报率再决定是否进 `src/`（修正案 1 纪律）。

**③ `type_suspect` 的正确形态：溯源矛盾，而非词形矛盾。** `PLACE_SUFFIX` 的失败与批 65「不是称谓 ≠ 是本名」同类——排除式判定在中文人名上必然失效。改为：**canonical 命中题材包官职/尊称词表（闸门第 4/5 步的已验证词表），而 P4 投票类型为 PERSON** → `type_suspect`。`老父台`、`范学台` 正是此类。复用已验证词表，不发明新规则。

### 3.7 修正案 5：④ 号检测器（互斥共现）**暂停产出**（2026-10-16 批 80/81）

一期验收的独立核对（`_wb_audit_verdict.md`）给出**一条站得住的误报证据**与**一次被证伪的新形态预演**：

1. **误报（已确证）**：`贾珍⇄贾珠` 同姓、全书从不共段 → ④ 判「疑似同一人被拆」，
   而原文中二人是**同族不同人**。⇒ 「同姓 + 互斥共现」筛出的是**关系疏远的不同人**。
2. **重设计预演失败**：候选新形态「别名语义重叠」（A 的别名 == B 的规范名）在**两书上均 0 命中**
   （直连 SQL 复核：`entity_aliases` 与 `entities.normalized_name` 无任何跨实体命中）
   ⇒ 该形态**无信号**，不采用。

## 四、闭环：判定结果的三条路径

不确定性建模如果只「标记」不「反馈」，那是报告，不是架构。

| 路径 | 内容 | 成本 | 风险 |
|---|---|---|---|
| **① 回图谱** | 判定结果作为独立元数据叠加，读时合并 | **$0** | 无（删表即还原） |
| **② 回题材包** | 外部资料显示某称谓/后缀从未被识别 → 词表有洞 → 补词 | ⚠️ **付费** | **打破 $0 可预演** |
| **③ 回评测** | 「不确定性覆盖率」成为一项指标 | **$0** | 无 |

**路径 ① —— 只标注，不改结构**

判定结果**不写** `entities` / `relationships`，只在读取时叠加。用户看到「**太祖**（原文仅称太祖，本名未确定）」，而不是一个假装完整的「太祖」。

核心价值：现在的图谱**把「确定的」和「猜的」画得一模一样**。标注之后，图自己会说话。

**路径 ② —— 唯一危险的一条**

若外部资料反复显示某称谓/后缀**从没被识别过**（如「老父台」「学台」），说明闸门词表有洞。

⚠️ 这条**会改 P1 的输入 → 直接打破 $0 可预演**。因此**不能自动执行** —— 只能产出「**待补词候选表**」，人工确认后走**显式记账**的付费重跑。

**路径 ③ —— 覆盖率成为指标**

现在只报 F1。补上：系统能对多少知识**表态**、其中多少「已解决」、多少「确认不可知」。

**优先级**：①②③ 里**只有 ② 需要付费**。所以「先做检测」与「先上搜索」不冲突 —— 检测 + ①③ 现在就能做完；② 等搜索结果攒够了一次性做。

## 五、数据模型与消费

### 5.1 核心决策：检测不落库，判定落库

| | 存哪 | 理由 |
|---|---|---|
| **检测结果**（5 类标记） | **不落库**，读时算 | 是图谱的确定性派生；落库只会引入 stale |
| **判定结果**（外部知识） | 独立表 `external_knowledge` | 有成本、需缓存、需可复核 |

**为什么不把检测结果落库**：

- 检测是**图谱的确定性派生** —— 读时算，永不失效、$0、纯函数可测。
- 落库会引入**过期问题**；更严重的是，要挂进 `persistGraph` 就属于**导入期代码** → 触发项目里「改导入期必须重导」的连锁后果。

### 5.2 表结构

```sql
create table external_knowledge (
  id            uuid primary key default gen_random_uuid(),
  book_id       uuid references books(id),        -- null = 跨作品通用
  subject_type  text not null,                    -- 'entity' | 'relationship'
  subject_key   text not null,                    -- 规范名 / 端点对
  field         text not null,                    -- canonical_name | biography | hometown
                                                  -- | courtesy_name | prototype | relation_note
  value         text,
  resolution    text not null,                    -- 'resolved' | 'disputed' | 'unresolvable'
  source_urls   text[] not null default '{}',
  snapshot_hash text,                             -- 抓取内容哈希
  confidence    text not null,                    -- 'high' | 'medium' | 'low' | 'none'
  fetched_at    timestamptz not null,
  created_at    timestamptz not null default now()
);

create unique index external_knowledge_key_idx
  on external_knowledge (coalesce(book_id, '00000000-0000-0000-0000-000000000000'),
                         subject_type, subject_key, field);
```

**两个设计要点**：

- 唯一键含 `field` → 「补名」与「简介」是**两条独立记录**，可分别重跑、分别回退。
- **「查过了，查不到」也要落库**（`resolution = 'unresolvable'`）—— 否则每次重跑都要重查。

### 5.3 消费方式：读时叠加

```ts
const snapshot    = await loadGraphSnapshot(bookId);
const uncertainty = computeUncertainty(snapshot);        // $0 派生 · 纯函数
const external    = await loadExternalKnowledge(bookId); // 独立表
// UI 分区展示，不合并进 snapshot
```

**三条铁律**：

1. **不写图谱表** —— `entities` / `relationships` 一个字节都不动。
2. **不进评测口径** —— 金标、变异锚点、审计脚本不引用这两者。
3. **UI 分区** —— 「本书信息」与「外部资料 · 全书视角」视觉分开，用户一眼能看出哪条来自哪里。

### 5.4 外部知识的定位：证伪，不证真

| | 原文 | 模型参数知识 | 外部检索 |
|---|---|---|---|
| 跨过信息边界 | ✗ | ✓ | ✓ |
| 有出处可复核 | ✓ | ✗ | ✓ |
| 可复现 | ✓ | ✗ | ✗ |
| 错误面 | 小（误读） | **大（幻觉，且查不出来）** | 中（UGC 会错，但看得见） |

参数知识与外部检索**都能跨过边界**，但只有外部检索**留下了出处**。搜索比「让模型自己回忆」强，**不是因为搜得更准，而是因为错了能追**。

**根本局限**：外部资料**擅长证伪，不擅长证真**。

- 能说「这名字查不到 → 可疑」✅
- 能说「百科写的是另一个名字 → 可能错了」✅
- **不能**说「这条关系对」❌ —— 百科讲的是**历史人物**，书里是**文学形象**；一致不等于书里就是这么写的

**所以外部知识只产出「疑点」与「置信度」，不产出「事实」** —— 它标注，不改写。

## 六、分期与验收

| 期 | 内容 | 成本 |
|---|---|---|
| **0 期**（修正案 3） | 金标最小扩展：补儒林 13–15 回一个切片（覆盖中后段规范名问题，如马纯上） | **$0**（一次性人工标注，无 LLM） |
| **一期** | 检测能力（`src/lib/graph/uncertainty.ts` 纯函数 + 读侧）+ 覆盖率指标 | **$0** |
| **二期** | UI 分区展示（标出「不确定」）—— **与一期捆绑交付**（修正案 4：检测单独交付的用户价值≈0，UI 分区才是价值出口） | **$0** |
| **三期** ✅ **已实现（批 84）** | 搜索 Agent + `external_knowledge` 表（判定）。~~前置~~ **已跑**（2026-10-16 `_wb_probe_rel_cooc.ts`）：单源关系中**约 75% 端点共现 ≥2 段**（儒林 205/274、红楼 177/235），近三成共现 >5 段（杜少卿⇄武书 35 段仅 1 条证据）→ **「召回不足」主导，「原文如此」仅约 1/4** ⇒ 搜索对单源关系不适用，修法在 P1 召回（付费域）。⚠️ 注意口径：共现 ≠ 该段必含关系证据，75% 是上界 | 搜索 $0 + 抽取 ≈$0.05 + ⚠️ **人工复核（主导成本，须入预算）** |
| **四期** | 路径② 词表补洞 | ⚠️ 付费 + 显式记账 |

**前置条件（必须先做）**：**先补尺子**。

现有金标只覆盖前几回，而规范名问题集中在中后段人物上（如 `马二先生` 在第 13–15 回）。**不扩金标就测不出效果** —— 即使搜索层修对了，读数也不会动。0 期只做**最小扩展**（儒林 13–15 回单切片），它同时承担两个角色：一期检测器置信度校准的取样池、三期判定验收的尺子。一个切片打通两期验收，避免在三期付费时重蹈批 49 尺子不可信的覆辙。

**验收标准**（修正案 2：覆盖率拆为双指标）：

- **一期**：① 检测的**误报率**（人工抽查 30 个标记）；② **可复现性**（同输入同输出）；③ **双指标** —— **表态率**（系统能对多少知识表态）+ **自知准确率**（抽查标记中正确的比例）。没有自知准确率，无法区分「好的不确定性系统」与「吵闹的不确定性系统」（两者覆盖率可以一模一样）。
- **三期**：判定命中率（人工抽查，以 0 期扩展后的尺子为准）。
- **明确不做的验收项**：**不进金标、不进变异锚点** —— 增强层的数据**永不参与**解析质量的评测口径。

## 七、明确不做（YAGNI）

- 外部知识**不改写**图谱结构（只标注）
- 外部关系**不生成边**（小说虚构，外部资料不能覆盖文学设定）
- **不自动改**题材包词表（须人工确认 + 显式记账）
- **不做**全量逐实体搜索（`sparse` 档 743 个网上没有资料，搜了白跑）

## 七之二、三期实施结果（批 84）

**已落地**：`external_knowledge` 表（迁移 `0002`）· `src/server/modules/knowledge/`（触发集/检索器/判决/仓库）·
`scripts/knowledge-agent.ts`（离线 Agent，`--book/--subject/--limit/--dry-run/--force`）·
读侧 `read-knowledge.ts` + 详情卡「外部资料 · 全书视角」独立分区（虚线上边框分隔）。

**试点实测**（真实检索快照，总成本 $0.0009）：
`建文皇帝 → 朱允炆`（resolved/high）· `王熙凤 → 贾琏之妻，贾府实际管家…`（resolved/high）·
`王举人 / 余二老爹 → unresolvable`（无资料、未调用模型、已缓存）。浏览器双分支均验收通过。

**检索源现状（重要）**：本环境**无可用的免 key 检索源**（维基被墙 · 百度百科 403 · DuckDuckGo 超时；
cn.bing / sogou 仅 HTML 页面，抓取违反 ToS 且脆弱，**不内置**）。因此提供可插拔 `SearchProvider`：
`FixtureProvider`（离线快照，默认用于测试与复现）+ `HttpJsonProvider`（配 `SEARCH_API_URL`/`SEARCH_API_KEY` 即用）。
🚨 未配置检索源时 Agent **显式报错退出**，绝不静默降级为「用模型记忆猜」。

**流程编排（批 86）**：新增 `analyze --with-knowledge` 后置钩子 —— 解析成功后自动跑判定层，
**用户视角是一条命令，数据仍是两处**（图谱 + `external_knowledge`）。
钩子用 try/catch 包裹且 `requireProvider: false`：**未配置检索源或增强失败都不改变解析的成功语义**。
独立入口保留：`pnpm knowledge:agent --book <书名> [--subject ...] [--force] [--dry-run]`。

**第二个实测缺陷（批 86）**：快照缺失原被当作「查不到」（返回空命中）→ 判定层会把
「**我们根本没搜过**」写成 `unresolvable`，后续运行见键即跳过、永远补不上（缓存污染）。
已修：新增 `SearchUnavailableError`，快照缺失时 reject；run-agent 捕获后**跳过且不落库**，
单列 `skippedSearch` 计数 —— 与「检索了但零结果」严格区分。

**试点暴露并已修正的设计缺陷**：「模型没写 `used_urls`」曾被保守规则降级为 `unresolvable` ——
那会把**查得到的对象缓存成查不到**（后续运行直接跳过，永远修不回来）。已改为：保留值 + 置信度降 `low` +
来源回落为本次命中前 3 条（出处仍可复核）。另新增 `--force` 用于口径变更后的重跑。

## 九、架构定位与后续优化候选（评审增补）
