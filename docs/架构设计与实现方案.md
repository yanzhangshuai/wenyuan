## 二、为什么重写：两个版本的确定缺陷（已核实到代码）

### v1 `wen-yuan` — UI 是资产，管线有硬伤

1. **prompt 膨胀**（token 消耗主因）：`src/server/modules/extraction/extractor.ts:41-56` 的 `buildExtractionUserPrompt` 每片拼入 **整片正文 + 全书摘要（≤2000 字）+ skill 全文 + 关系码**。约 35K token/片，《儒林外史》全书 Pass1 输入 35–40 万 token，**无 prompt 缓存**。
2. **分片粗糙**：`extraction/slices.ts` 的 `DEFAULT_SLICE_SIZE=6`（6 章/片），**无重叠**，边界只在章节处。
3. **重试放大 9 倍**：`analysis/jobs/runAnalysisJob.ts:50` 片级重试 3 次 × `AiCallExecutor` 内层 `maxRetries+1=3`；且 `AiCallExecutor.ts:74` 把"输出非 JSON"也列为可重试，稠密片截断时反复重试。
4. **领域知识注入是死代码**：`identity/prompts.ts:22` 定义了 `IDENTITY_KNOWLEDGE_SKILL_SLUGS` 但**全仓无引用**，`identityPass.ts:125` 调用时未传 skills。
5. **归并靠字符串精确匹配**：`identity/aliasResolver.ts:47-57` Union-Find 仅按 alias 精确桥接，无空白/大小写归一；`identity/projection.ts:79-87` 吸收实体按 `name` 精确匹配，差异即导致 `mentions` 重指向丢失。
6. **评测从未跑通**：`scripts/goldset/` 真实金标仅 **7 章**（儒林外史 ch01/02/03/32/46 + 歧路灯 ch001/002）；门禁 `entityF1≥0.74 / relationF1≥0.68` 已定义，但 **`scripts/eval/results/` 不存在，无任何通过留档**。

### v2 `wenyuan_new` — 工程规范好，但范围失控

- **41 张表**（已逐一核对 `= pgTable(` 定义）、7 个 worktree、跨章编排一整套重型机制。
- **放弃分片**：`analysis/runs/create-run.ts` 把整章段落拼接一次性塞进模型，无 token 分片、无滑动窗口。
- **砍掉身份 AI Pass 且未替换**：文档 §3.3 声称歧义时交给 AI 判断，代码里只有确定性匹配 + 人工决策。
- **无 CI**（无 `.github`）。停在 Phase 4，Plan 5「质量验收」完全未开始。

### 值得继承的 5 项（来自 v2）

1. 单章 run 闭环 + **运行快照**（冻结 model/prompt/skills）+ 事务内原子应用 → `analysis_runs`
2. Prompt/Skill 与代码分离、版本化
3. **证据定位的确定性校验**：模型只回 `quote+prefix+suffix`，服务端唯一匹配落坐标，多义即判 INVALID
4. 确定性身份匹配 + 人工归并 + 可撤销（带 revision 乐观锁）
5. **关系有效期契约** `OBSERVE/BEGIN/END` → 聚合为 `INSERT/EXTEND/CLOSE`，未结束用 `end_chapter=null`

### 参考项目 AI-Reader-V2 的高准确率机制（关键借鉴）

准确率**不靠 prompt 技巧，靠确定性工序**：

1. **预扫描词典锚定**：jieba + ngram + 后缀规则统计候选实体 → LLM 分类成白名单
2. **grounding 子串匹配（零 LLM 成本）**：对全库 corpus 做字面匹配，无证据的名字直接剔除
3. **独立二审，数据路径隔离**：二审只读原文 + 影子表，**机制上读不到一审结果**，不靠 prompt 自觉
4. **关系类型投票** + 保守 tie-break
5. **别名安全护栏**：`_is_unsafe_alias` 防止"大哥/妈妈"这类泛称桥接
6. **截断 JSON 修复**：去 ``` 围栏 + 补括号（`_repair_truncated_json`）

其 prompt 全文（约 10KB + 19KB few-shot）已取得，**最有价值的是大量具体反例**，例如：
- 「❌ 把地名子串当人名：文中"韩国"不表示有人物叫"韩"」
- 「❌ 自己和自己建立关系：A 的别名 B 不应与 A 建立关系」
- 「❌ 把师兄弟当成师徒」「❌ 把结拜兄弟当成上下级」
- 「❌ 父子/父女性别搞错：'只有一女，乳名英莲' → 甄士隐-英莲 = **父女**（不是父子！）」
- 别名禁止规则：明确排除代词与自称（吾/我/汝/在下/老夫/贫道/朕/寡人）、假想身份、外观状态描述、泛类身份、临时指称；**梦境/幻觉中的角色是独立角色**

## 四、数据模型（Drizzle，首版 12 张）

| 表 | 关键字段 | 索引 / 说明 |
|---|---|---|
| `works` | id, title, author, status, chapter_count | |
| `chapters` | id, work_id, ordinal, title, raw_text | `(work_id, ordinal)` 唯一 |
| `paragraphs` | id, chapter_id, ordinal, text | **证据定位锚点** |
| `entities` | id, work_id, canonical, **normalized_name**, type, name_type, faction_index | `(work_id, normalized_name)` 唯一 |
| `entity_aliases` | id, work_id, entity_id, alias, **normalized_alias** | `(work_id, normalized_alias)` 唯一 |
| `entity_mentions` | id, paragraph_id, entity_id, surface, **normalized_surface**, start, end | FK → entities |
| `relationships` | id, work_id, source_entity_id, target_entity_id, relation_type_code, direction, **start_chapter, end_chapter**, status | 双向索引 |
| `relation_types` | code, category(0–4), direction | `category` 对齐 `edgeTypeColors` 下标 |
| `evidence_spans` | id, paragraph_id, start, end, quote | |
| `analysis_runs` | id, work_id, status, model_snapshot, prompt_version, skill_snapshot | 冻结快照 |
| `analysis_calls` | id, run_id, stage, model, tokens_in, tokens_out, cost, latency, error_kind | 审计 + 成本 |
| `analysis_issues` | id, run_id, chapter_ordinal, code, payload | 片级问题留档 |

### 四个关键设计决策

1. **邻接表 + 递归 CTE 支持路径查询**：`relationships` 即邻接表，建 `(work_id, source_entity_id)` 与 `(work_id, target_entity_id)` 两个索引；无向遍历用 `UNION` 双向。最短路径 = 递归 CTE 做 BFS，用 `visited int[]` 去环、`WHERE depth < 6` 剪枝。章节时间轴筛选把 `start_chapter/end_chapter` 作为 CTE 的 `WHERE` 条件。当前规模（约千点 / 数千边）完全够用；图更大时再物化闭包表。

2. **修复 v1 的 mentions 丢失**：根因是靠名字字符串回填。**所有名字落库统一经 `normalizeName()`（去空白/全角、大小写折叠）写入 `normalized_*` 列并建唯一索引；归并只改 `entity_mentions.entity_id` 外键，永不靠名字回填。**

3. **保留 v2 的关系有效期契约**：`aggregateRelationship()`（纯函数，`INSERT/EXTEND/CLOSE/ISSUE`）照搬，`OBSERVE/BEGIN/END` 存于候选 envelope。零风险，且解决「师徒反目、夫妻离散」的时序问题。但**不引入** `analysis_batches` 整套编排表。

4. **表数量控制在 12 张**（v1 = 19，v2 = 41）。

## 五、解析管线（核心：同时降成本 + 提准确率）

| 阶段 | 输入 → 输出 | 模型档 | 量级 |
|---|---|---|---|
| **P0 预扫描词典** | 全书段落 → jieba + ngram + 后缀规则（先生/老爷/知县/府/县…）→ 候选频次 → 小模型分类成**锚定白名单** | 便宜 | 全书 1 次 ≈ 5K |
| **P1 分片提取** | 片 → 候选 JSON（persons/aliases/relationships/events + evidence） | 便宜 | **4–6K/片** |
| **P2 grounding** | 候选名 → corpus 子串匹配，无字面证据即剔除 | **0 LLM** | 0 |
| **P3 独立二审** | 只读 `paragraphs` + 词典（**机制上读不到 P1 结果**）→ verdict(`entity_exists` / `name_supported`) | 便宜/中 | 仅未决候选 |
| **P4 类型投票** | 同 pair 多片类型多数投票，tie-break 保守 | 0–1 | 0 |
| **P5 归并 / 别名** | Union-Find(normalized) + 不安全别名黑名单 + canonical 决策 | 0（可选 embedding） | 0 |
| **P6 关系聚合** | `aggregateRelationship` → 落库 | **0 LLM** | 0 |

### 为什么能同时降本 + 提准

- **降本**：v1 每片 35K input（整片正文 + 全书摘要 + skill 全文）。新版 P1 只给「本片正文 + **本片相关锚点 Top-N**（非全量）+ 前序滚动上下文（≤300 字摘要 + 上片出场名）」→ 目标 **4–6K input/片**，约 **降低 85%**。
- **提准**：不靠 prompt 技巧，靠 P2/P3/P4 三道**确定性工序**与**数据路径隔离**。P2 与 P6 零 LLM 成本。

### 具体策略

- **分片**：改为**字数驱动滑动窗口**，3000–4000 字/片、重叠 300–400 字（1–2 段），边界优先段落；章内 >8000 字再切。重叠导致的同关系重复，用 pair 去重 + P4 投票消歧。
- **prompt**：system 存固定规则 + **压缩 few-shot 反例（5–8 条）**；前缀保持稳定以命中 **prompt cache**。user 只拼本片正文与滚动上下文。
- **结构化输出**：Zod → JSON Schema → `response_format`；截断走 `repair-truncated-json`（去围栏 / 补括号）。
- **重试策略（修正 v1 的 9 次放大）**——按**错误类别**分流：
  - `output_not_json` / `truncated` → **不重试**，走 repair 或**重新切更小的片**
  - `rate_limit` / `5xx` / `timeout` → 指数退避，≤2 次
  - `schema_invalid` → 一次带错误信息的修复调用，再失败则丢弃该片并写 `analysis_issues`
  - 片级重试与执行器内层重试**不叠加**，统一由 `AiCallExecutor` 管理。最坏调用数 **9 → ≤2**。
- **成本控制**：模型分级（粗筛便宜档 / 精修与仲裁强档按需）、并发 semaphore、增量（仅新章）、断点续跑（`analysis_runs` + 章级 status）、月预算。
- **归并 blocking**：先用 normalized + 后缀规则分组；embedding 仅对未决簇（首版可延后）。

## 六、准确率验证体系（让准确率可证明）

- **goldset**：沿用 v1 `scripts/goldset/{schema.ts,标注规范.md}`（可直接迁移，其 Zod schema 已定义 `canonical/type/nameType/aliases/firstAppearancePara/activeChapters` + 悬空引用交叉校验）。规模从 7 章扩到 **≥20 章**（儒林外史 15 + 歧路灯 5）。
- **指标**：沿用 `scripts/eval/evaluate.ts` 的**微平均 F1**（跨章累计 TP/FP/FN 后计算，比章节级平均更稳）。实体 F1 = 名字集合（canonical ∪ aliases，normalized）命中且类型一致；关系 F1 = typeCode + 两端命中，`SYMMETRIC_CODES` 允许方向互换。
- **防虚高**：precision 分母含全部 ext 实体（含误报）；额外报告「grounding 通过率」「跨章实体一致性」两个辅助指标。
- **门禁**：`entityF1 ≥ 0.74`、`relationF1 ≥ 0.68`（沿用）。结果**必须落档** `data/evals/<book>/results.json` —— v1 缺此目录、从无通过证据。
- **回归**：`scripts/eval/run-eval.ts` 对固定 goldset 跑并输出 diff。
- **CI**：建 GitHub Actions 跑 lint + type-check + unit + eval —— v2 无 CI 是没跑完的结构性原因。

## 九、风险与取舍

| 风险 | 应对 |
|---|---|
| **react-force-graph-2d 重建成本最高**（v1 交互 1446 行） | 若 Canvas 达不到视觉/交互要求，**回退保留 D3 SVG**（代价：栈内加 d3） |

| 递归 CTE 性能 | 当前规模 OK；图更大时物化闭包表 |
| embedding blocking 依赖外部服务 | 首版先用字符串归一 + 后缀规则，效果不足再加 |
| goldset 扩标是人力瓶颈 | 先做 20 章，不追求全 56 回 |
| P3 独立二审收益不显 | 按需触发，可整体旁路，不影响主链路 |
| **WSL 路径读写** | 用 `//wsl$/Ubuntu/...` UNC 形式；`wsl.exe` 被安全策略禁用，不可调用 |
