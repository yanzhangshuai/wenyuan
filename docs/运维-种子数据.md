# 运维：种子数据与部署顺序

> 适用：首次部署、换库、以及每次发布后的重复执行（全部幂等）。

## 一条命令

```bash
pnpm db:seed
```

它做两件事：

| 项 | 内容 | 幂等方式 |
|---|---|---|
| 关系类型字典 | 把 `src/lib/relations.ts` 的 `RELATION_TYPES` 同步进 `relation_types`（10 条） | 以 `code` 为主键 upsert |
| 管理员账号 | 按 `ADMIN_EMAIL` 建号；已存在则**重置密码、提为 ADMIN、重新启用** | 按邮箱 upsert |

**不会删除任何既有数据**，重复执行安全。

## 部署顺序（固定四步）

```bash
pnpm install
pnpm db:migrate      # 建表（14 张）；忘了这步 db:seed 会提示「表结构未就绪」并退出 2
pnpm db:seed         # 种子数据
pnpm build && pnpm start
```

## 管理员配置（写在 `.env` 里）

种子脚本会**主动加载仓库根的 `.env`**，所以直接写进 `.env` 即可，无需在命令行传参：

```bash
# .env
ADMIN_EMAIL=admin@your-domain.com
ADMIN_PASSWORD=<至少 8 位，建议 16 位以上随机串>
ADMIN_NAME=管理员        # 可选
ADMIN_USERNAME=admin     # 可选
```

> 实现细节：`getServerEnv()` 是惰性的（首次连库才加载 `.env`），而种子在连库**之前**就要读
> `ADMIN_*`，因此脚本入口显式调用 `ensureEnvLoaded()`；有契约测试钉住这个顺序。
> 生产也可用真实环境变量：Node 的 `loadEnvFile` **不覆盖**已存在的环境变量，
> 因此同名时以**进程环境变量**为准。为避免困惑，同一变量只在一处写。

行为矩阵：

| 情况 | 行为 | 退出码 |
|---|---|---|
| 两项都未设置 | 只同步字典，打印建号提示 | 0 |
| 两项都设置 | 建号或重置密码 | 0 |
| **只设置其中一项** | **报错，不写入任何数据** | 2 |
| 密码 < 8 位 / 邮箱非法 | 报错，不写入 | 2 |
| 加了 `--skip-admin` | 忽略环境变量，只同步字典 | 0 |

「半个配置就报错」是有意的：只给邮箱不给密码时若静默跳过，部署者会误以为账号已建好。

## 其它模式

```bash
pnpm db:seed --dry-run        # 只检查表结构与配置，不写入（发布前预演）
pnpm db:seed --skip-admin     # 只同步字典；管理员另行创建
pnpm seed:admin --email ... --password ...   # 只改管理员密码（生产找回访问权）
pnpm seed:relation-types      # 只同步关系类型字典
```

## 两种身份：管理员 / 用户

| | 管理员（ADMIN） | 用户（VIEWER） |
|---|---|---|
| 来源 | `pnpm db:seed`（读 `.env` 的 `ADMIN_*`） | 登录页「注册」自助创建，或数据库直接插入 |
| 登录落点 | `/admin`（后台） | `/`（书库首页） |
| 后台 `/admin` | 可访问 | **被弹回 `/`** |
| 写操作（导入等接口） | 允许 | 403 |

两者的登录入口是同一个 `/login`，落点由**角色**决定（`resolvePostLoginRedirect`）。
普通用户即使手动访问 `/admin`，也会被后台守卫弹回首页，不会看到任何后台内容。

## 安全约定

- 日志只打印 `主机:端口/库名`，**从不打印连接串中的账号密码**；
- 不打印任何密码明文；
- 种子命令不做 `DROP` / `TRUNCATE`，也不删除既有用户。

## 与鉴权的关系

种子只负责「有账号可登录」，会话签名还依赖 `JWT_SECRET`（≥32 字节）写入 `.env`：

```bash
printf '\nJWT_SECRET=%s\n' "$(openssl rand -base64 48)" >> .env
```

未配置时登录接口返回 500，但后台与种子命令本身不受影响。
