## 一、项目是什么

**文渊 v3** —— AI 小说人物关系图谱构建器。

- **输入**：一本中文古典小说的全文 txt（当前有《儒林外史》57 回、《红楼梦》120 回）
- **输出**：人物实体 + 别名 + 关系边构成的知识图谱，网页端可视化浏览
- **立项时的两个痛点**：token 成本过高、解析准确率过低
- **核心方法论**：**用确定性工序替代 prompt 技巧**来同时降本与提准

## 二、核心架构（必须先理解这条，它决定了所有后续设计）

### 「LLM 当算子」的固定流水线，**不是 agent**

- **无 tool calling、无自主循环、无 agent 编排**
- **恰好 2 个 LLM 调用点**（写死在 `run.ts`）：
  - `dictionary`（P0）：1 次/本
  - `extract`（P1）：1 次/片
- 其余所有阶段都是**确定性纯代码**（0 LLM）
- 因此**成本线性可预测**：调用次数 ≈ 1 + 片数，跑之前就能算出来

**这条是本项目的地基**。任何「把搜索 / 工具调用 / 二次推理塞进管线」的改动都会摧毁「成本可预测」与「$0 预演」两个能力，必须先论证。

### 七阶段

| 阶段 | 做什么 | LLM |
|---|---|---|
| P0 预扫描词典 | jieba + n-gram + 后缀规则统计候选 → 小模型分类成锚定白名单 | ✓ 1 次/本 |
| P1 分片提取 | 每片正文 → 候选 JSON（人物/别名/关系/证据引文） | ✓ 1 次/片 |
| P2 grounding | 候选名 → 全库字面匹配，无字面证据即剔除 | ✗ |
| 实体闸门（8 步） | 列举式规范名 → 泛称 → 姓氏+氏 → 尊称 → 官职 → 身份/职业 → 收 | ✗ |
| P4 类型投票 | 同 pair 多片类型多数投票，tie-break 保守 | ✗ |
| P5 归并 / 别名 | Union-Find + 不安全别名黑名单 + **canonical 决策** | ✗ |
| P6 关系聚合 | `OBSERVE/BEGIN/END` → `INSERT/EXTEND/CLOSE` | ✗ |

> 立项时设计过 **P3 独立二审**，实施中发现收益不显，**已删除**。

### 三层题材包（genre pack）

`通用 → 古典（中式称谓/官职/姓氏+氏）→ 具体书`。已验证：加《红楼梦》包**未改任何控制流**，接口充分。

### 🚨 三个必须知道的事实

1. **读数不可复现**：同代码 + 同输入，实体 F1 会跳 **±7 点**（`temperature: 0` 下仍不可复现）。**单次读数不可直接归因** —— 分不清「改进了」和「运气好」。因此判据是「**方向 + 机制**」，不是 F1 差值。
2. **两本书版本不一致**：代码里 `PROMPT_VERSION = "2026-10-02.1"`；儒林库已重跑对齐，**红楼库仍是旧版 `2026-10-14.2` 的产物**。这是已知债务，台账在 `~/.workbuddy-ai/verify/_wb_known_inconsistency_ledger.md`。
3. **金标只覆盖前几回**，覆盖不到中后段 —— 而部分缺陷恰好集中在中后段人物上。**有些问题现在测不出来。**

### 已知缺陷

- ✅ **已修**：规范名被选成称谓（`马二先生` → 应为 `马纯上`）。根因是 `pickCanonicalKey` 按**频次**选规范名，而称谓出现次数必多于本名。

## 六、工作纪律（踩坑总结，请当规则遵守）

1. **判据是「方向 + 机制」，不是 F1 差值** —— 因为有 ±7 点本底噪声。
2. **不碰 P1 输出的改动，先做 $0 确定性预演**：库内精确重放，把预测写成表，跑完逐条对账。⚠️ 前提是 V0 能逐条复现（FP/FN 名单全等），否则预演作废。🚨 预演**必须 import 真实的评测函数**，禁止自写指标。
3. **「我找不到」≠「它不存在」**。判断某服务是否存在，唯一可信的判据是**按真实协议直连一次**；`netstat` / `find` / 目录列举都是**可能整片失效的间接证据**。
4. **「坏的是尺子」是最常见的错误**。任何检测器 / 度量写完后，都要问：**它量的对象对吗？**（例：用「地名后缀表」判人名类型 → `江/山/亭` 是人名常用字，误报一片；用「编辑距离」检同一人 → 中文人名噪音 >90%。）
5. **检测器本身也需要被验证** —— 检测结果应带自身置信度，不能假定「$0 算出来的」就等于「对的」。
6. **纯函数覆盖率 ≠ 功能正确**。「决策函数」和「调用点」是**两个必须分别钉住的被测对象**。jsdom 不绘制 canvas → 「渲染后断言颜色」不可行 → 需要**读源码文本的接线契约测试**。
7. **变异自测**：新增断言必须做变异验证（故意改坏代码，确认测试能杀掉）。还原后用 `diff -q` 二次校验。
8. **改导入期代码（`persistGraph` 等）必须重导**：重导 = 同名作品整体替换 → 级联清空该作品的 entities / relationships / mentions / analysis_runs。所以**优先选「读时计算」而非「落库」**。
9. **断言前必须剥注释** —— 否则「解释性注释」会被判成违规（把解释当违规 = 量错对象）。

## 九、当前方向

**不确定性建模** —— 目标是「**让系统能意识到自己的不确定**」，而不是「补全缺失」。

核心分界：**检测 $0 / 判定付费**。

- **检测**（五类：本名缺失 / 同人歧义 / 类型存疑 / 同段落共现 / 关系单源）**只依赖图谱自身** → 确定性、$0、可预演 → 可整体进 `src/`
- **判定**（需要外部知识）→ 走独立离线 Agent，**不改写图谱、只标注**
